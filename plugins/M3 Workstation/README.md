# M3 Workstation (by Shannon)

A 6-voice, two-oscillator subtractive synth for Akai MPC standalone hardware.
This is the first milestone of a Korg M3-inspired workstation. Combinations,
drum kits, sample playback, effects and the arpeggiator come in later stages.

## Parameters

| Page   | Control       | Range               | Default |
|--------|---------------|---------------------|---------|
| OSC    | Volume        | -40 .. +6 dB        | -6 dB   |
| OSC    | Osc1 Wave     | Sine/Triangle/Saw/Square | Saw |
| OSC    | Osc2 Wave     | Sine/Triangle/Saw/Square | Saw |
| OSC    | Osc2 Semi     | -12 .. +12 st       | 0       |
| OSC    | Osc2 Detune   | -50 .. +50 ct       | +7      |
| OSC    | Osc Mix       | 0 .. 100 %          | 50 % (0 = osc1 only, 100 = osc2 only) |
| FILTER | Cutoff        | 20 Hz .. 18 kHz     | 3 kHz   |
| FILTER | Resonance     | 0 .. 100 %          | 20 %    |
| FILTER | Filter Env    | -100 .. +100 %      | 40 %    |
| ENV    | Attack        | 1 .. 5000 ms        | 5 ms    |
| ENV    | Decay         | 1 .. 5000 ms        | 250 ms  |
| ENV    | Sustain       | 0 .. 100 %          | 70 %    |
| ENV    | Release       | 1 .. 5000 ms        | 300 ms  |

Filter envelope amount opens the cutoff by up to four octaves.

## Programs

Init, Pad, Pluck, Bass, Lead.

## Requirements

- MPC OS 3.10.1 or later.
- Enable External plugins on the device: Preferences → Enhancements (Beta) → Enable Enhancements and External Plugin Support.

## Sample playback (Source = Sample)

The SAMPLE page switches the voices from the oscillators to multisample playback.

- **Source**: Synth or Sample. **Instrument**: 1-32, the instruments listed in `Content/Instruments/index.txt`, in that order.
  **Loop**: use the sample's loop points (off = play once).
- Samples are mono or stereo WAV (stereo is mixed to mono), 4-point Hermite interpolation, any sample rate.
  Pitch follows the key, root note, and per-region tune (cents). Keys with no sample stay silent.
- Region pan is applied. Region level is read but **not applied yet**. Pitch bend is not handled in sample mode yet.
- The filter and amp envelope apply to samples. Use the **Sample Pad** program (filter wide open) as a starting point.
- Instruments load once when the plugin starts. Restart the plugin after changing `Content/`.
- Total sample memory is capped at 48 MB; extra regions are skipped.

### Getting Korg-format samples in

`tools/korg_samples.py export FILE.KMP Content/` converts a Korg multisample (.KMP with its .KSF files) into the
WAVs and keymap this plugin reads. Only use samples you have the right to use. No samples are bundled with the plugin.
Other tools in `tools/`: `korg_pcg_read.py`, `decode_pcg2.py` (read Korg .PCG program banks).

## Tests

`test/render_test.cpp` is a small host that loads the built plugin and checks pitch, loop, release, tuning, zones and pitch bend:

    python3 test/make_synth_content.py /tmp/m3synth/Content
    g++ -std=c++17 -o render_test test/render_test.cpp -ldl
    MPC_PLUGIN_FOLDER=/tmp/m3synth ./render_test build/native/m3-workstation.so synth

## Filter, key tracking, LFO (parameters 16-21)

| Parameter | Range | Effect |
|---|---|---|
| Filter Type | Lowpass / Highpass / Bandpass / Notch | State-variable filter mode |
| Key Track | 0-100 % | Cutoff follows the key around middle C |
| LFO Shape | Sine / Triangle / Square / S&H | One shared free-running LFO |
| LFO Rate | 0.1-20 Hz | |
| LFO Depth | 0-100 % | The mod wheel (CC1) adds to this |
| LFO Dest | Pitch / Cutoff / Amp | Pitch = +/-2 semitones, Cutoff = +/-2 octaves, Amp = tremolo at full depth |

Pitch bend is +/-2 semitones. The skin (`skins/`, regenerated by `tools/make_skin.py`) is a drawn hardware-style
front panel: the program list, graph and keyboard on it are pictures, not controls. The four header buttons are real (SYNTH/SAMPLE = Source, LOOP, LFO ON).

## Master effects (parameters 23-28, FX page)

Signal chain after the voice mix: chorus -> stereo delay -> reverb. Chorus Mix; Delay Mix / Time (10-1000 ms) / Feedback
(0-90 %, repeats cross between L and R); Reverb Mix / Size (Freeverb-style, 8 combs + 4 allpasses per channel).
Buffers are allocated in prepare(); process() does no allocation. CPU use has not been measured on ARM.

## Arpeggiator (parameters 29-35, ARP and ARP 2 pages)

Arp On, Mode (Up / Down / Up-Down / Random / Order played / Chord), Rate (1/4, 1/8, 1/8T, 1/16, 1/16T, 1/32, synced to the
host tempo; 120 bpm if the host gives none), Gate 10-100 %, Octaves 1-4, Swing 0-50 %, Latch. Notes you play are held by the
arp and re-triggered as a sequence; other MIDI (pitch bend, mod wheel) passes straight through. A new arp can start up to one
audio block (<= 512 samples) late. "Arp Lead" is a program with the arp on.

## Drum mode (Source = Drum; parameters 36-38, DRUM page; program "Drum Kit")

Built-in kit: original synthesized drums on the General-MIDI-style notes 35-59 (kicks, snares, clap, rim, hats, toms, cymbals,
cowbell). Open, closed and pedal hats share a choke group; 8 drum voices; velocity changes level and brightness. Drum Tune
(+/-12 st) and Drum Decay (50-200 %) apply to the whole kit. Drum Kit = Sample plays the selected instrument's key map as
one-shots (no loop, note-off ignored). Per-drum tune / level / pan / filter editing is not implemented: values per drum are fixed
in `src/DrumSynth.h`, because a VST parameter list can't hold per-note settings. The drum bus follows Volume and is soft-limited.

## Combination mode (Mode = Combi; parameters 39-40, COMBI page)

Mode = Combi plays a *combination*: up to 4 parts, each a built-in program with its own key range, velocity range, transpose,
level and pan. Combination chooses one of 7 built-ins: Pad + Pluck (layer), Bass / Lead (keyboard split), Velocity Switch (soft =
Pluck, hard = Lead), Layer Stack (3 parts, one an octave up), Drums / Lead (split), Sample + Pad, Octave Bass. Each sounding note
keeps its own copy of its program, so the parts really play different sounds at once. In Combi mode the knobs and Mode-independent
effects/LFO/arp still apply to the whole mix; the knobs do not edit the parts. 12 voices shared by all parts (oldest is stolen).
Not implemented: editing combinations, 16 parts, per-part mute/solo/MIDI channel/effects routing. The combination list is in
`src/M3Workstation.cpp` (`kCombis`).

## Factory preset bank

Programs 8 and up are 116 original presets across 19 categories (Piano, Electric Piano, Organ, Bass, Lead, Pad, Strings, Brass, Synth, Bells, Plucks, Drums, Percussion, FX, Cinematic, Hip-Hop, R&B, Trap, Dance). Names are `TAG Name` (at most 23 characters). Four are combinations (Mode = Combi). Pianos are synth approximations; there are no sampled pianos and no Korg content.

- `presets.json` lists each preset's index, category, description, tags and parameter values.
- `tools/make_presets.py PLUGIN_DIR` regenerates `src/Presets.inc` and `presets.json`. `tools/preset_gain.json` holds the per-preset Volume found by level calibration (target rms about 0.07, peak at most 0.5; one preset is capped at +6 dB).
- Test: `render_test build/native/m3-workstation.so presets` renders every preset and checks it is finite, audible and below full scale.

## Reading Triton programs

`tools/triton_program.py FILE.PCG [--json out.json]` decodes the 540-byte PCM programs in Triton-family PBK1 banks (name, oscillator mode, both oscillators' sample numbers and levels, pitch, filter A/B, filter and amp EGs, LFOs, arpeggiator, effect types), using the layout in Korg's TRITON MIDI Implementation, Table 1. It reads parameters only: Triton programs point at ROM or RAM sample numbers, so the audio itself is not in a PCG. Checked on 1,280 programs: every field is in its legal range, and the arpeggiator tempo matches the Rose IV author's published list for all 128 sounds.

## Importing Triton programs as presets

1. `python3 tools/triton_to_m3.py Content/Presets/user.m3p [TAG=]BANK.PCG [...]` (for example `RO4=ROSE4.PCG`) decodes Triton PCM programs (540-byte) and Triton MOSS programs (604-byte, EXB-MOSS) and writes up to 4096 approximate presets (empty slots and factory-blank "InitlProgram" slots are skipped; a program that exactly copies another program in the same bank is dropped too, as the TR-808 bank's 125 unused slots are copies of one template).
2. Put `Content/Presets/user.m3p` next to the plugin's other Content. The plugin loads it at start-up (after the 116 factory presets); no rebuild is needed. Lines that are malformed are skipped.

**Approximate by design.** Triton PCM programs point at samples in the Triton's own ROM or RAM, which a PCG does not contain, so the preset uses this plugin's oscillators. What carries over: amp envelope (times use an approximate curve), filter cutoff (floored at 150 Hz), resonance, type, envelope amount and key tracking, the strongest LFO routing, oscillator-2 interval and detune, arpeggiator on/off, direction, octave range and gate (attack is capped at 40 ms when the arpeggiator is on), and drum mode. Triton effect settings are not mapped. Instead, converted presets get category effect defaults (reverb, chorus and delay amounts from the `FX` table in `triton_to_m3.py`, unmeasured starting values; bass, drums and hits stay dry). A program whose source has every effect switched off stays dry, so the TR-808 kicks get no effects. Modulation matrix routings and tempo sync are not mapped. Converted presets are not level-matched by the converter (`tools/level_match.py` does that as a separate step).

`tools/triton_moss.py` decodes MOSS banks (checked on a 128-program bank: all the fixed bytes in Table 2-1 hold). Divided-bank PCGs (a directory chunk plus bank-name entries, as in `TimoMoss.PCG`) are read too. Note: in real files the MOSS filter type and EG selector are stored 1-based (1 = LPF, 5 = Amp EG); Korg's Triton table lists them from 0. This was confirmed on 256 programs, where 0 never occurs. Test: `render_test ... userpresets` loads every user preset and checks it is finite, audible and below full scale.

### Level matching converted presets

On a computer: build the plugin, put the file in `Content/Presets/user.m3p`, then
`CAL_OUT=cal.tsv render_test m3-workstation.so userpresets` and `python3 tools/level_match.py user.m3p cal.tsv user_matched.m3p`.
This uses the same rule as the factory bank (rms about 0.07, peak at most 0.5). Volume tops out at +6 dB, so very dark or slow-attack sounds can stay quieter than the rest.

### Skin note (device, MPC X, 2026-11-18)

On the first run on an MPC X the switch segments (Source, Filter Type, LFO Shape and so on) showed no text: the page-level label components the generator adds did not draw. `tools/make_skin.py` now gives each switch its own copy of the switch definition with the text drawn into the segment images. Not yet re-checked on the device.

### Preset names

VST2 programs are one flat list (no folders), so converted names carry their group: `TAG CAT Name`, for example `RO4 GTR Picking like Rai`. TAG is the bank you gave on the command line; CAT is the Triton program category (KEY ORG BEL STR VOX BRS WND GTR BAS SLO FST LED MOT SFX HIT DRM, in Korg's order 0-15; the order was checked against the Rose IV author's own category list, which matched for all 15 categories it uses). Within a bank, presets are grouped by category. Names are at most 24 characters (the VST2 limit).

### More sample instruments (1.2.0)

Up to 32 sampled instruments (Instrument 1-32, in `Content/Instruments/index.txt` order). `korg_samples.py export FILE.KMP CONTENT_DIR NAME` takes an optional name, for sets whose multisamples all carry the same placeholder name (seen: six sets all named `NewMS______000`). Very quiet source recordings can be peak-normalised after export (a gain change only).
